# مهرة للمزودين (تطبيق الهاتف)

Expo SDK 58 + TypeScript، عربي RTL وإنجليزي. على الحاسوب يُعرض داخل إطار هاتف في الوسط (نسخة الويب).

```bash
cd mahra/apps/provider && npm install
npx expo start --web   # أو npm run web
npx tsc --noEmit && npx eslint .
```

## الفكرة
المزود يفتح التطبيق ليعرف ثلاثة أشياء فقط: **أين الشغل الآن؟ كم أربح؟ ماذا عليّ لمهرة؟** والتصميم فاتح عالي التباين وأزراره 52pt لأنه يُستعمل في الشمس وبيد واحدة.

| الشاشة | لماذا تجذب المزود |
|---|---|
| **الفرص** | مفتاح «متاح» ولؤلؤة ذهبية نابضة، وطلبات قريبة بعدّاد مهلة، وربح اليوم. إن كان غير متاح: «فاتتك 3 طلبات هذا الأسبوع» (معلومة صادقة لا ضغط). |
| **عرض السعر** | يكتب سعره فيرى فوراً: ما يراه العميل، وما يحصل عليه **كاملاً**، وعمولة مهرة **فوق** سعره لا منه. هذا يشجعه على سعره الحقيقي. |
| **العمل** | خطوات واضحة (قبلت ← في الطريق ← بدأت ← أنجزت)، واتصال/واتساب/اتجاه بنقرة، وتسجيل ما حصّله فعلاً (تُحسب العمولة عليه). |
| **العمولات** | مبلغ مستحق وعدّاد بأيام العمل وتنبيه قبل الموعد، بدل إيقاف مفاجئ. رفع إثبات التحويل. |
| **ملفي** | حلقة اكتمال الملف وحالة كل وثيقة (ناقصة/قيد المراجعة/مقبولة/مرفوضة مع السبب)، وأدائه. |

## ما اختُبر (متصفح، 390×844 وسطح مكتب، بلا أخطاء كونسول)
الدخول، عرض السعر بمعاينة 150 ← 180 ← عمولة 30، إرسال العرض، رفض تحصيل أكبر من المتفق عليه، تسجيل التحصيل وظهور عمولة مستحقة بموعدها، رفع إثبات يشترط مرجعاً وصورة، وحالات الحساب (موقوف/ناقص).

## ما هو محاكاة / ما ينقص
- **البيانات تجريبية في الذاكرة** (`src/lib/store.tsx`) وتعكس مخطط القاعدة؛ تُستبدل بنداءات الخلفية دون تغيير الشاشات.
- **رفع الوثائق والصورة** أزرار شكلية؛ الرفع الحقيقي مع التخزين.
- **حساب مهرة البنكي** مكانه نص «يُضاف من الإدارة».
- **الإشعارات الفورية** (طلب جديد، اختيارك، موعد العمولة): غير مبنية، وهي أهم ما يجعل المزود يرجع للتطبيق.
- **الأوردو والهندية**: أولوية قبل الإطلاق، فكثير من السائقين لا يقرؤون العربية ولا الإنجليزية بطلاقة.
- `src/lib/pricing.ts` نسخة من تطبيق العميل؛ تُستخرج لحزمة مشتركة كي لا تنحرف.
