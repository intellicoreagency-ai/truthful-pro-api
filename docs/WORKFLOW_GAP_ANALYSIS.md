## Decisions recorded from the owner (20 Nov 2026)
1. `ready_for_authority` = "Ready to submit", separate from "With authority"; the latter needs the real submission reference; the customer bar stays five stages.
2. Delivery uploads are saved for review only; nothing is visible until "Publish to customer"; acknowledgement belongs to the published package version.
3. Document override: authorised member, after review; records reason, overridden rule, member and date; internal approval only; never bypasses file-safety checks.
4. **Official WhatsApp number +971585144005** is for communication and, in future, request notifications through an authorised integration. **No real messages are sent now.** Opening a `wa.me` link proves nothing: the app treats WhatsApp verification as done only when the signed Meta webhook receives the customer's message. Any future outbound message must be recorded by its provider status, never inferred from opening WhatsApp.
5. Finance (Phase 3) next, with **no VAT in this phase**: the VAT rate stays a setting that is off, documents are "Invoice" not "Tax Invoice", and nothing may zero out VAT that is owed or issue a real tax invoice until the accounting setup is approved.

- **Security review fixes** (`a8cfd70`): customers can no longer cancel/reset a request once it is filed or finished nor edit its data after review starts (submit only from draft; cancel only while draft/submitted/review/needs_documents; conditional write); agents can no longer lift a failed document rule by a manual pass, a back-dated reference date or re-reading the expiry (a manual pass can never replace an unresolved failure: only the audited override can). Found by a security-review pass, confirmed by reading the code, covered by tests that fail when the flaw is re-introduced.
- **Batch 4e**: **real malware scanner integrated** (ClamAV via `scanner-service`, `SCANNER_MODE=clamav-http`; see DEPLOY.md). Verified locally against a real `clamd` (clean file -> clean, file containing the EICAR string -> rejected with 422, scanner down -> pending, never clean) using a local test signature, because this sandbox cannot reach ClamAV's signature servers; **production still needs the owner to host the service with live signature updates and re-test with EICAR**. Added owner/manager rescan of pending files. The customer account (app) and the dashboard now show the **full transaction cost = Company fee + government fees** (government part paid directly to the authority). 95 API tests.
- **Batch 4d**: the invoice for the Company fee is issued **automatically** when the customer submits (per-service fee table `service_fees`, owner/manager, dashboard page "Company fees"; migration 0011) and is visible in the customer app at once. A service without a configured fee is priced manually. The official government fee is looked up on the authority portal and attached once afterwards with its official pay link (cannot be changed). **Not built:** the push/WhatsApp *delivery* of the invoice to the customer (no outbox or approved message template; messaging stays off), so "sent" currently means "appears in the app"; per-transaction fee adjustments need cancel + manual re-issue. 93 API tests; finance browser flow passes.
- **Batch 4c** (owner clarification): there is no customer-facing quotation. After the customer has uploaded documents, finance issues an **invoice for the Company's own fee only** (the customer pays it in advance by bank transfer or cash). Government fees are shown on it as information only; the customer pays the authority and keeps the authority's own receipt. The quote acceptance route and screen were removed; the fee statement is frozen at issue and re-pricing needs the invoice cancelled first. **Override** is confirmed as: owner/manager may accept a document that failed the system's check (e.g. the system cannot read the image, or a government concession applies) with a written reason, audited and never visible to the customer; never for malware, signature or size. 92 API tests; finance browser flow passes.
