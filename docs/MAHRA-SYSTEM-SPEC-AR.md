# مهره — مواصفات النظام الكامل (ثلاثة تطبيقات)

> يبني على `MAHRA-PRODUCT-AR.md` (القرارات) و`MAHRA-DESIGN-AR.md` (الهوية). الصور المرجعية إلهام لا قيد.
> ما ليس مؤكداً من المالك موسوم بـ **[افتراض]** ويُراجع قبل البناء.

## 0. الفكرة في خمسة أسطر

- **مهره** تطبيق مجاني يحل مشكلة العميل خطوة بخطوة عبر 15 وكيلاً مختصاً.
- **تطبيق المزود** يستقبل طلبات العروض ويكتب سعره ويُنجز العمل ويدفع العمولة.
- **تطبيق المدير** (ويب) يتحكم: اعتماد المزودين، العمولات، الضريبة، الإيقاف، الإيرادات.
- **نظام خلفي واحد** يربط الثلاثة، ووكلاء ذكاء، وروبوت استقطاب المزودين.
- الإيراد: عمولة 20% (قابلة للضبط حسب الخدمة) على كل دفعة تُحصَّل. لا دفع داخل التطبيق.

## 1. خريطة النظام

```
العميل (مهره) ──طلب──▶ مهره (منسّقة) ──تحويل──▶ وكيل مختص
                                          │ يشخّص ويطلب عروضاً
                                          ▼
                              محرك الطلبات (Requests Engine)
                    ┌──────────────┼───────────────┐
                    ▼              ▼               ▼
             تطبيق المزود   روبوت الاستقطاب   تطبيق المدير (ويب)
          (يرد بالسعر ×1.0)  (يبحث ويدعو)   (يعتمد، يحصّل، يوقف)
                    └── السعر النهائي للعميل = السعر × 1.2 ──┘
```

### الكيانات الأساسية
| الكيان | أهم الحقول |
|---|---|
| العميل | هاتف، واتساب (علامة تحقق)، لغة، مدينة، سيارات/عناوين محفوظة |
| الطلب (Request) | عميل، وكيل مالك، فئة خدمة، وصف/صور/موقع، حالة، سجل تحويلات |
| عرض (Offer) | طلب، مزود، سعر المزود، سعر العرض للعميل (×1.2)، مدة الوصول، ملاحظات |
| المزود | شركة، فئات، مناطق (دبي/الشارقة…)، وثائق، حالة (أحمر/أخضر/موقوف/ملغى)، تقييم |
| العمل (Job) | عرض مقبول، دفعات (مبلغ، تاريخ)، حالة |
| العمولة | job/دفعة، المبلغ المستحق (20% من سعر المزود)، الاستحقاق، الحالة، إثبات التحويل |
| الضريبة | قيمة 5%، مرجعها، الفترة |
| المحادثة | وكيل مالك، رسائل، حزمة التحويل (Handoff Packet)، حالة (نشطة/موقوفة/مستأنفة) |

### حالات الطلب
`مسودة ← تشخيص ← طلب عروض ← عروض واردة ← مقبول ← قيد التنفيذ ← مكتمل`
جانبية: `منتهي المهلة`، `ملغى`، `نزاع`.
عند قبول عرض: تُغلق باقي العروض آلياً.

### حالات العمولة
`مستحقة (3 أيام عمل) ← إثبات مرفوع ← [مطابَق: مدفوعة | بحاجة مراجعة] ← متأخرة ← مزود موقوف (آلياً)` وللمدير override في أي خطوة.
**[افتراض]** الاستحقاق يبدأ عند تأكيد المزود إنجاز الخدمة، لا عند قبول العرض.

## 2. اتجاه التصميم المشترك

مراجعة نقدية: الكحلي الداكن مع الذهبي والزجاج هو اتجاه الصور، لكنه شائع في تطبيقات «الفخامة». لذا نصرف الجرأة في **عنصر واحد**: **اللؤلؤة (Pearl)**، كرة زجاجية حية هي هوية مهره، وكل ما حولها هادئ ومنضبط.

| العنصر | القرار |
|---|---|
| ألوان أساسية (رموز) | حبر `#060A18` · كحلي عميق `#0B1530` · لؤلؤي `#EDE7DA` · ذهب دافئ `#D9B66B` · ياقوت `#3D63DD` · فيروزي `#6FC7D1` |
| دلالات | نجاح `#3FA58A` · تحذير `#E0A33C` · خطر `#D8584E` (لا لون وحده؛ دائماً أيقونة/نص) |
| الخط | عائلة تدعم العربية واللاتينية والسيريلية: مقترح IBM Plex Sans Arabic + Plex Sans (يُختبر مع روسي وغيره)؛ حجم أساسي 16، تباعد أسطر 1.6 للعربية |
| الشكل | زجاج مقروء بتعتيم كافٍ (تباين 4.5:1)، حواف 20–28، ظل واحد متدرج، لا بطاقات متطابقة بلا هرمية |
| الحركة | حالات اللؤلؤة فقط (استماع/تفكير/رد/صمت) + استجابات للفعل (فتح/تأكيد). لا حركة زخرفية على كل قسم. تقليل الحركة = بدائل ثابتة |
| الاتجاه | RTL أولاً، وينعكس كل شيء (الأيقونات الاتجاهية، التمرير الأفقي، علامة السداد) |
| لغة النص | أفعال بسيطة، «احفظ» لا «إرسال»، الأخطاء تشرح الحل، الفراغ دعوة للفعل |
| إمكانية الوصول | أزرار ≥ 44×44، تكبير الخط، قراءة شاشة، تباين، بدائل للصوت (نص) |

**فروق بين التطبيقات:**
- **مهره (العميل):** داكن، دافئ، صوتي، اللؤلؤة بطلة.
- **المزود:** **فاتح عالي التباين** (يُستخدم في الشمس بالطريق)، أزرار كبيرة، لؤلؤة صغيرة كعلامة فقط.
- **المدير (ويب):** كثيف بالبيانات، فاتح/داكن، جداول ولوحات، لؤلؤة في الشعار فقط.

## 3. تطبيق مهره (العميل)

### 3.1 الصفحات
**الدخول والبداية**
1. **ترحيب + اللغة** (عربي افتراضي؛ تتبع لغة الجهاز).
2. **رقم الهاتف + رمز تحقق** مع مربع إجباري «على هذا الرقم واتساب»، وحقل رقم واتساب بديل إن لم يكن.
3. **أذونات مشروحة** (ميكروفون، موقع، كاميرا، إشعارات): كلٌّ في لحظة حاجته لا دفعة واحدة.

**الأساسية (شريط سفلي: الرئيسية · طلباتي · [ميكروفون] · المختصون · حسابي)**
4. **الرئيسية الصوتية:** اللؤلؤة، اقتراحات سريعة بحسب السياق (طلب نشط، قريب منك)، آخر طلب.
5. **المحادثة (صوت/نص/صورة/موقع):** رسائل، حالة اللؤلؤة، زر إيقاف، مرفقات، شارة الوكيل الحالي.
6. **المختصون (الاستوديو):** 15 وكيلاً مرتبون بحسب الاستخدام، بطاقة لكل واحد (أيقونة، دور، سطر)، ضغطة تدخل حديثه.
7. **ملف المختص:** من هو، ماذا يفعل، أمثلة، «ابدأ».

**الطلبات (قلب المنتج)**
8. **طلباتي:** قائمة بحالتها (قيد العروض، مقبول، قيد التنفيذ، مكتمل)، شريط تقدم.
9. **تفاصيل الطلب:** ملخص المشكلة، الوسائط، الخط الزمني.
10. **مقارنة العروض (حتى 3):** السعر النهائي فقط، اسم المزود، التقييم، وقت الوصول، «اختر». رقم المزود **مخفي حتى القبول** **[افتراض]**.
11. **اختيار طريقة الدفع:** بطاقة أو نقد (يدفع للمزود مباشرة) + تأكيد.
12. **تتبّع التنفيذ:** حالة المزود، اتصال/واتساب بعد القبول، موقعه إن كان في الطريق.
13. **إنهاء وتقييم:** تقييم + «هل تم الاتفاق خارج التطبيق؟/بلّغ عن مشكلة».

**الشخصية**
14. **سياراتي** (للمختص جلال: النوع، الموديل، اللوحة اختياري)، **عناويني** (للمنزل والعمل).
15. **الإشعارات** (مركز) و**الإعدادات** (لغة، صوت، تقليل حركة، حجم نص).
16. **الخصوصية وبياناتي:** تصدير/حذف، مدة الاحتفاظ.
17. **المساعدة والطوارئ:** أرقام طوارئ، «أبلغ عن مشكلة»، شروط وسياسة.

### 3.2 السلوك الجوهري
- **التحويل بين الوكلاء:** مهره تعلن بوضوح «أحوّلك لطلال»، ويظهر الوكيل بشارته. **الوكيل الأول يحتفظ بمحادثته** ويستأنف عند العودة. العميل لا يعيد شيئاً (حزمة التحويل).
- **لغة العميل:** تتبعه في منتصف الحديث (عربي → روسي) وكذلك الصوت.
- **الصور:** يرفعها العميل للتشخيص؛ يُعالج الوكيل ويسأل أسئلة قليلة.
- **السلامة أولاً** (جلال): خطر على الطريق ⇒ إرشاد فوري قبل أي عرض.
- **عدم الاتصال:** المحادثات المحفوظة قابلة للقراءة؛ الطلبات المعلقة تُرسَل عند عودة الشبكة.

## 4. تطبيق مزود الخدمة

### 4.1 الصفحات
**التسجيل والاعتماد**
1. **دخول** (هاتف + OTP) و**دعوة من روبوت الاستقطاب** (رابط خاص).
2. **الملف التعريفي:** اسم الشركة، الفئات (يختار من فئات الوكلاء)، مناطق التغطية (دبي، الشارقة…)، ساعات العمل، لغات.
3. **رفع الوثائق:** الرخصة التجارية، عقد الإيجار، موقع Google Maps، الهاتف، واتساب (مع علامة تحقق)، بقية المعلومات. كل وثيقة: حالة (مطلوبة/مرفوعة/مقبولة/مرفوضة مع السبب) وتاريخ انتهاء.
4. **شروط الاتفاق:** عمولة 20%، مهلة 3 أيام عمل، قبول إلكتروني. لا دخول بدونها.
5. **حالة الاعتماد:** تُظهر ما ينقص. يبقى **غير فعّال** حتى تكتمل الوثائق ويعتمد المدير.

**الاستخدام اليومي (شريط: الطلبات · أعمالي · العمولات · حسابي)**
6. **الرئيسية:** زر «متاح/غير متاح»، طلبات جديدة عاجلة، ملخص العمولات المستحقة.
7. **الطلبات الواردة:** بطاقة لكل طلب مع **مؤقت** للرد، المسافة، الوسائط. «اقبل/ارفض/تجاهل». الرفض يحوّل الطلب آلياً لمزود آخر.
8. **تفاصيل الطلب:** صور المشكلة، التشخيص، الموقع على الخريطة.
9. **كتابة العرض:** خانة السعر + عرض فوري لـ«السعر الذي سيراه العميل» (×1.2) و«عمولة مهره 20%». ملاحظات، مدة الوصول/التنفيذ.
10. **أعمالي:** قيد التنفيذ، مكتمل. تحديث الحالة: «في الطريق»، «وصلت»، «أنجزت».
11. **إنهاء العمل:** تأكيد الإنجاز والمبلغ المحصَّل ⇒ تنشأ العمولة.
12. **المعاينة المسبقة** (ديكور/مقاولات): تسجيل زيارة ثم إرسال العرض بعدها، ودفعات مرحلية.

**العمولات**
13. **محفظة العمولات:** المستحق، تاريخ الاستحقاق، عدّاد 3 أيام عمل، حساب مهره البنكي (آيبان) ونسخة بنقرة.
14. **رفع إثبات التحويل:** صورة/PDF + المبلغ والمرجع؛ حالة (قيد المراجعة/مدفوع/بحاجة تصحيح).
15. **سجل العمولات والإيصالات.**

**الحساب**
16. **التقييمات والشكاوى**، 17. **الإحصاءات** (طلبات، قبول، إيراد)، 18. **الإشعارات** (push + واتساب + بريد)، 19. **الإعدادات واللغة**، 20. **الدعم**.
21. **شاشة الإيقاف:** سبب واضح («عمولة متأخرة»)، المبلغ، كيف يُسدَّد، رفع إثبات، قناة تواصل مع المدير. لا إلغاء صامت.

### 4.2 قواعد مهمة
- ما يراه المزود هو **سعره** هو، لا سعر العميل، إلا في معاينة الحساب.
- التنبيه العاجل بطريقة لا تفوّت: push ثم واتساب ثم اتصال.
- منع التحايل: لا رقم عميل قبل القبول **[افتراض]**، إغلاق الطلب داخل التطبيق شرط.

## 5. تطبيق المدير (ويب)

### 5.1 الصفحات
**نظرة عامة**
1. **لوحة القيادة:** طلبات اليوم، عروض، إنجازات، إيراد العمولات، مزودون جدد/موقوفون، تنبيهات (عمولة متأخرة، نزاع، فشل وكيل).

**المزودون**
2. **خط الاعتماد (Pipeline):** مدعوون ← أكملوا الوثائق ← بانتظار المراجعة ← معتمدون. **نقطة حمراء/خضراء** بجانب اسم الشركة.
3. **ملف المزود:** الوثائق (عارض + قبول/رفض بسبب)، تاريخ الانتهاء، التقييم، الأعمال، العمولات، سجل الشكاوى.
4. **إجراءات:** إيقاف / تفعيل / إلغاء الحساب (بسبب: غير كفء، مشكلة مع عميل، سوء أدب، تحايل، أخرى) + سجل تدقيق لا يُحذف.

**العمولات والمال**
5. **لوحة العمولات (Radio):** لكل طلب «هل سُدّدت عمولة مهره؟» **نعم / لا**؛ فلتر (متأخرة، بانتظار مراجعة). تذكيرات آلية قابلة للإرسال يدوياً.
6. **مراجعة الإثباتات:** صورة التحويل + ما استخرجه OCR (مبلغ، تاريخ، مرجع) + مطابقة مع كشف الحساب. اعتماد/رفض/تعديل.
7. **إيرادات مهره:** العمولات المحصَّلة بحسب الفترة/الفئة/المزود، وتتبّع المتوقع.
8. **مخصصات الضريبة:** القيمة 5%، المرجع، الفترة، تصدير للمحاسب.
9. **قواعد العمولة:** نسبة افتراضية 20% + استثناءات لكل فئة؛ مهلة السداد؛ شروط الإيقاف الآلي.

**العمليات**
10. **الطلبات المباشرة:** كل الطلبات بحالتها، البحث، التدخل اليدوي (إعادة توجيه، إلغاء، تعويض).
11. **المحادثات والتصعيد:** محادثات مشكوك فيها (أمان، شكوى، طوارئ)، قراءة بصلاحية مقيدة وسجل.
12. **النزاعات والبلاغات:** من العملاء (تحايل، سوء خدمة).
13. **العملاء:** قائمة، حظر، حذف بيانات (طلب خصوصية).

**الذكاء والاستقطاب**
14. **الوكلاء:** لكل وكيل: الشخصية، الصوت، المصادر، حدود التخصص، نسخة التعليمات، نتائج التقييم.
15. **روبوت الاستقطاب:** حملات (فئة × منطقة)، قائمة المرشحين من البحث، حالة الدعوة، حدود الإرسال، قائمة «لا تتواصل».
16. **مصادر المعرفة:** الدلائل والمراجع (مثل دليل المالك)، تاريخ التحديث.

**النظام**
17. **المستخدمون والصلاحيات (RBAC):** مدير عام، مالي، دعم، مراجعة وثائق. 18. **سجل التدقيق.** 19. **الفئات والخدمات.** 20. **الإشعارات والقوالب.** 21. **الإعدادات** (لغات، مناطق، حدود).

### 5.2 المسح الآلي للإثبات
`رفع ← OCR ← مطابقة (مبلغ + مرجع + تاريخ + حساب) ← [مطابَق: مدفوعة آلياً + علامة] | [غير مطابَق: بحاجة مراجعة للمدير]`
كل تسجيل آلي قابل للتراجع من المدير ومسجّل.

## 6. مبادئ مشتركة

| المجال | القرار |
|---|---|
| اللغات | عربي أولاً؛ لغة مهره تتبع المتحدث؛ نصوص الواجهة قابلة للترجمة (i18n) من اليوم الأول |
| الاتجاه | RTL/LTR تلقائي؛ علامة السداد يمين المعاملة (عربي) ويسارها (لاتيني) |
| الأمان | تحقق هاتفي، RBAC، تشفير، سجل تدقيق، صلاحيات مقيدة لقراءة المحادثات، نقل بيانات وفق القانون الإماراتي |
| الخصوصية | أقل قدر من البيانات، حذف بطلب، صور الوثائق تُخزَّن مشفّرة بصلاحيات للمدير فقط |
| الأداء | نص يظهر فوراً، الصوت يبدأ سريعاً، صور مضغوطة، فتح مباشر لأي حالة (Deep Links) |
| الإشعارات | push + واتساب + بريد؛ تصنيف: عاجل/عادي/تسويق (لا تسويق دون إذن) |
| المراقبة | تتبّع أخطاء، تكلفة النماذج لكل محادثة، لوحة صحة الوكلاء |

## 7. أبعاد مستقبلية

**المراحل**
1. **أ:** مهره + جلال + مزودو السطحات + لوحة مدير مصغّرة؛ دبي والشارقة.
2. **ب:** بقية الوكلاء، تطبيق المزود الكامل، روبوت الاستقطاب، OCR.
3. **ج:** خدمات المعاينة والدفعات المرحلية، ضبط العمولة بحسب الفئة.
4. **د:** كل الإمارات، حسابات المتاجر، شراكات.
5. **هـ:** توسع خليجي، لغات إضافية.

**أفكار لاحقة:** مستويات مزودين (ذهبي بتقييم عالٍ مقابل أولوية ظهور)، سجل صيانة ذكي للسيارة، تذكير بالصيانة الدورية، تأمين/ضمان، عملاء شركات (أساطيل)، مهره في السيارة (CarPlay/Android Auto).

**أهم المخاطر**
| الخطر | الضابط |
|---|---|
| تحايل (اتفاق خارج التطبيق) | إخفاء الرقم حتى القبول، بلاغات، تنبيه نمط مشبوه، إلغاء بضغطة |
| عدم سداد العمولة | استحقاق واضح، تذكير آلي، إيقاف آلي بعد 3 أيام عمل، override |
| إثبات تحويل مزوّر | OCR + مطابقة بنكية + مراجعة |
| تشخيص خاطئ | مصادر موثقة، حدود التخصص، إحالة لورشة، إخلاء مسؤولية |
| تكلفة الذكاء | نماذج متدرجة، سقف يومي، تخزين مؤقت للإجابات الشائعة |
| روبوت الاستقطاب | قيود واتساب للأعمال وقواعد هيئة الاتصالات، حد يومي، «إلغاء» فوري |
| الاعتماد على مزوّد واحد | أكثر من مزوّد لكل فئة ومنطقة |
| قانوني/ضريبي | محاسب لتحديد وعاء الـ5%؛ شروط استخدام واضحة |

**مؤشرات النجاح:** زمن أول عرض، نسبة الطلبات المنتهية بعرض مقبول، متوسط تقييم المزودين، نسبة العمولات المحصَّلة في المهلة، نسبة الاتفاقات الخارجية المشتبه بها، تكلفة الذكاء لكل طلب مكتمل.

## 8. ترتيب البناء المقترح
1. أساس monorepo (Expo/TypeScript) + أنواع مشتركة + i18n/RTL + نظام الألوان واللؤلؤة.
2. مهره: دخول، رئيسية صوتية، محادثة، المختصون (نموذج بيانات تجريبي).
3. الخلفية: طلبات، عروض، عمولات (Supabase أو ما يناسب الاستضافة الإماراتية).
4. مسار جلال كاملاً (تشخيص ← سطحة ← عروض ← قبول).
5. تطبيق المزود: وثائق + طلبات + عرض + عمولات.
6. تطبيق المدير: اعتماد + لوحة العمولات + إثبات.
7. الوكلاء الباقون، الاستقطاب، OCR.
